# 05 · BM25

## Why keyword search still matters

Embeddings capture meaning, not exact strings. "E-4012" becomes sub-word tokens whose vector roughly means "some error code," so E-4012 and E-4021 look nearly identical. The same applies to SKUs, version numbers, clause numbers, names, and internal jargon.

| Query | Vector search | BM25 |
|---|---|---|
| "error code E-4012" | Misses: codes look interchangeable | Finds it: exact rare-token match |
| "how much vacation do I get?" vs. "paid time off" | Finds it: understands synonyms | Misses: no shared words |

## The formula

score(D, Q) = Σ over query terms t of **IDF(t) × TF part(t, D)**

**IDF (rarity):** `IDF(t) = ln(1 + (N − n + 0.5) / (n + 0.5))`, where N = total chunks and n = chunks containing t.

**TF part (frequency, length-normalized):**
`f × (k1 + 1) / (f + k1 × (1 − b + b × len(D) / avg_len))`

- `k1 = 1.2` controls saturation (repeats help less each time).
- `b = 0.75` controls length normalization (long chunks don't win by default).

## Worked example: "error code E-4012"

Corpus: 1,000 chunks, average length 100 tokens.

| Term | Chunks containing it | IDF |
|---|---|---|
| error | 300 | 1.20 |
| code | 200 | 1.61 |
| e-4012 | 2 | 5.99 |

| Chunk | Contents | Score |
|---|---|---|
| A (E-4012) | 100 tokens; error, code, e-4012 once each | 1.20 + 1.61 + 5.99 = **8.80** |
| B (E-4021) | 100 tokens; error ×2, code ×2 | 1.375 × (1.20 + 1.61) = **3.87** |
| C (general) | 200 tokens; error ×5 | 1.55 × 1.20 = **1.86** |

B mentions the common words more often but scores less than half of A, because A contains the one rare term.

**What BM25 returns:** chunks sorted by score. Chunks containing none of the query terms score 0 and are not returned.

## Saturation

| Occurrences | 1 | 2 | 5 | 10 | 100 |
|---|---|---|---|---|---|
| TF part (average length) | 1.00 | 1.38 | 1.77 | 1.96 | 2.17 |

Each term's TF part approaches k1 + 1 = 2.2.

## Why BM25 scores are unbounded

The total is a **sum over query terms**, each weighted by IDF, and IDF depends on corpus size. A one-word common-term query may top out around 2; a long query with rare terms can exceed 30. **A BM25 score only means something relative to other scores for the same query.** No fixed scale, no universal threshold. This is why hybrid search fuses ranks (RRF) instead of scores.

## Which chunks get scored: the inverted index

Query length decides **how many terms are summed per chunk**. The number of chunks scored depends on the **corpus**.

An inverted index, built at indexing time, maps each term to the chunks containing it:

```
"error"  → 300 chunks
"code"   → 200 chunks
"e-4012" → 2 chunks
```

At query time: look up each term, take the union of the lists (at most 502 candidates here), score only those, and sort. Chunks without any query term are never touched. Very common words have huge lists, which is one reason engines drop stop words, and their IDF is near 0 anyway. Engines like Elasticsearch also skip candidates that provably can't reach the top k.

## Practical notes

- **Scores differ by implementation.** `rank_bm25`, Lucene, and Elasticsearch use slightly different IDF variants; rankings usually agree.
- **Tokenization matters for identifiers.** `.split()` keeps `e-4012` whole. Many default analyzers split on hyphens into `e` and `4012`. Check how your engine tokenizes codes and SKUs.
